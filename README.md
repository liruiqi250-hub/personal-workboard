本项目无需 Docker。当前没有桌面 EXE 安装器。只监听本机回环地址，不能直接供其他电脑或手机访问。关掉浏览器页面后，后台仍会运行；电脑关机、休眠或服务停止时，不会继续采集或定时生成报告。

## 第一次使用

真实公开仓库为 [liruiqi250-hub/personal-workboard](https://github.com/liruiqi250-hub/personal-workboard)。本次选择 [GitHub发行列表](https://github.com/liruiqi250-hub/personal-workboard/releases)中实际存在的v0.3.6预览发行 的 `personal-workboard-0.3.6-windows-x64.zip`（含Node和生产依赖），大小与 SHA-256 以该发行的校验文件为准。`personal-workboard-0.3.6-public-source.zip`为干净源码，需另行安装依赖和构建。旧V0.3.2已有数据实例必须使用独立可信的新维护工具入口，不能调用旧更新脚本。

1. 将 ZIP 完整解压到自己的程序文件夹，不要在压缩包窗口里直接运行。
2. 双击 `scripts/首次部署.cmd`。系统会准备服务并通过默认外部浏览器打开页面。没有合适 Node 时，该脚本会从 **HTTPS 的 nodejs.org 官方站**下载固定 `v24.15.0` Windows x64 ZIP，校验官方 `SHASUMS256.txt`，仅存于本项目 `vendor/node`，不修改系统 PATH。此下载需要网络；仅支持 Windows x64。
3. 在页面填写自己的称呼、选择报告保存文件夹，再按向导配置需要的来源。不确定的账户信息保持待配置。
4. 以后双击 `scripts/启动看板.cmd`。已运行时会核对实例并复用，不重复启动。停止时双击 `scripts/停止看板.cmd`。

Windows 若提示文件来自互联网，先核对发行页作者、ZIP 的 SHA-256 和发行说明。企业电脑的组织策略可能禁止脚本运行，交由管理员按组织规则处理。脚本只为当次 PowerShell 进程使用执行策略参数，不永久修改机器策略。

若拿到的是源码 ZIP，或从 Git 克隆源码，在程序目录打开 PowerShell 执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\deploy.ps1 -DownloadNode -OpenBrowser
```

源码部署会执行 `npm ci`、`npm run build`，因此需要 npm 和网络。部署包已有生产依赖和构建结果，可执行 `deploy.ps1 -SkipInstall`。`-SkipInstall` 仅跳过安装，不能补齐缺失的依赖。

## 数据和报告放在哪里

程序目录只存放软件。任务、来源设置和历史记录默认在 `%LOCALAPPDATA%\PersonalWorkboard\workboard.sqlite`；本机加密凭据在同目录的 `credentials.dpapi.json`。凭据由 Windows 当前用户保护，复制到另一台电脑或另一个 Windows 账户后应重新授权。不要把这个数据目录放进公共仓库或发给同事。

报告原件保存在页面设置的“报告保存文件夹”，默认是数据目录内的“报告”。点击网页下载后，浏览器还可能在它自己的“下载”文件夹保存一份副本。更改报告原件目录不会改变浏览器下载设置。

电脑迁移时先停止服务，备份独立数据目录与自己设置的报告目录；在新电脑重新扫码和填写凭据。SQLite 数据库及其 `-wal`、`-shm` 文件应在安全停服后一同处理，不要让两个服务同时写一套数据。

## 来源接入、微信和 Codex

V0.3.1 增加两个具体采集适配器：微信指定版本源码工具读取本人的指定本机会话，钉钉官方 dws 读取已授权群及时间窗口。工具没有随本包安装，依赖、账号、稳定会话 ID 和真实兼容性仍需分别配置和验证。微信还必须提供该账号已授权的逐库离线密钥，由 Windows DPAPI 保存；本适配器禁止自动扫描微信进程内存和全局密钥缓存，缺少凭据即停止；详细步骤在 [INSTALL_FOR_CODEX.md](docs/INSTALL_FOR_CODEX.md)。也可继续使用明确标示的本机文件整理。微信文字读取会重新处理指定会话，已入库记录在 AI 前去重，不代表平台提供了原生增量游标。图片、语音、视频与附件正文未覆盖。

手动导入可以先用；邮件、微信、钉钉等渠道只有取得真实授权且测试成功后才算接入。未配置来源应显示待配置，测试或示例记录不代表已读取真实聊天。

微信二维码由服务按实际可用接口取得。请本人用手机扫码，核对接收微信并发送测试消息。登录、手机确认、验证码和第三方授权需要用户自己完成；Codex 不会代替用户扫码。二维码或接口不可用时，保留未连接状态，不能宣称微信已上线。

微信遥控默认关闭。需要先在本机启用、选择允许操作的项目，并确认本机 Codex CLI 可用。手机发送 `/codex 任务内容` 才会提交任务；普通聊天不会自动变成系统命令。涉及 Codex 自身审批的请求仍按其权限规则执行。

本看板创建的受管会话、最近会话、请求账本和完整结果保存于本机。服务重启后运行中的任务标为待核对，不自动重发、旧审批码失效；可明确发送 `/继续 最近 补充要求`，服务重新核对原会话和当前允许项目后再续接，不接管其他桌面聊天。超出当前远程审批支持范围的请求会被拒绝并转本机处理，不截断命令后授权。

报告页可以分别发送摘要或文件；微信也可发送“日报文件”“周报文件”。单文件上限为本软件设置的 20 MiB。只回传首次登记的报告、完整文字结果及本轮协议明确产出的受支持文件；不扫描整个项目。长文分段保留，上传、接口接受、发送不明和已读未知分别记录。结果不明时必须先在手机核对，再从本机手动重试未接受部分；旧审批通知不可重试。

平台返回“接受发送”只能证明接口接受，当前没有用户已读回执。日报完整性受真实来源覆盖范围影响。PDF 导出需要本机 Edge 或 Chrome；也可导出 Word 或 HTML。

## 升级、回退和诊断

V0.3.3 继承本项目仓库与 Ed25519 发布公钥，默认指纹为 `SHA256:65b116f1c4d1c91be3a108ed51051b29683d69654fed638065f8e9a30d7edebd`。正式通道只接受非草稿、非 Pre-release 的正式发行；预览通道要求固定标签，普通主服务只允许验签下载，不能安装预览或降级。既有明确自定义来源保留，公钥轮换由可信版本或可信安装流程交付。

本次开发预览在替换前建立完整、逐文件哈希可验证的旧程序副本和数据快照，并写入操作意图。快照与目标发行暂存保留；更新或回退中断后，根据完整恢复依据和当前已知哈希核对重试。未知内容、缺失原件或绑定冲突会拒绝并保留现场。V0.3.3历史最终ZIP验收已覆盖目录内占用、动作后记账前中断、回退失败重试、旧分裂记录恢复及版本/模式门；该缺口在新维护入口和这些已验路径内关闭，旧版算法仍有缺口。

**V0.3.2 首次迁移必须使用独立的新可信V0.3.6完整工具目录。** 从该目录运行 `scripts/maintenance.ps1 -Action Update`，明确指定旧 `-ProgramDir`、原 `-DataDir/-Port`、新 Windows 部署 ZIP、可信 `-ExpectedSha256` 和 `-ExpectedVersion 0.3.6`。这条路径不调用旧 V0.3.2 更新脚本，完整可复制步骤见 [安装指南](docs/INSTALL_FOR_CODEX.md#v036-首次迁移与旧失败记录恢复)。发布后从实际V0.3.6预览发行取得完整可信工具，目标ZIP与ExpectedVersion均应为0.3.6，首次迁移仍走外部maintenance入口。

已有旧 `needs-rollback` 记录时，同样从新可信工具目录使用 `-Action RecoverLegacy -PreviousDir`，提供当时失败目标的原 ZIP 与可信 SHA-256。模块核对原清单，把分裂在现场和 saved 中的旧原件完整重建到新快照；缺失、未知修改或冲突会拒绝，原现场保留。首次导入后的恢复若再次中断，按回执中的新事务目录使用 `-Action Rollback` 重试，保留第一次回退前数据。

回退会保留完整的回退前数据快照，再恢复旧程序和对应数据库、凭据。升级后新任务可从首次回退前快照核对，报告原件不删除；当前界面回到旧数据库的状态。程序目录、独立数据目录和报告目录分别保管。源码 checkout 或缺少原 `release-manifest.json` 的目录不能直接作为事务升级目标，需先受控部署完整 Windows 包并核对同一数据目录与实际数据完整性，不能声称已自动迁移。

核对快照中的任务时，先把完整快照复制到另一个独立目录，再打开副本。SQLite 查看工具即使选择只读，也可能在原目录生成 WAL/SHM 辅助文件；原密封快照只作哈希核对，保持原样供恢复重试使用。

诊断使用 `scripts/diagnose.ps1`。维护始终使用原数据目录和端口；脚本核对实例，不按旧 PID 强杀未知进程。维护、发版与完整恢复规则见 [RELEASE_FOR_CODEX.md](docs/RELEASE_FOR_CODEX.md)。

## Codex 任务分析（V0.3.6）

在“我的设置 → 任务分析方式”选择“Codex 分析（使用本机已登录账号）”。先检测连接，勾选同意将已选来源的消息文字发送到 Codex 服务，再用固定示例测试分析，最后保存。需要安装兼容的 Codex CLI 并由本人登录；不需要填写 API 地址或密钥。分析不更改微信遥控开关，不接管已有 Codex 会话。默认仍为本机规则，升级不会自动切换分析方式。

该模式不是本机离线模型。分析在独立临时目录运行，跳过用户配置及规则，禁用命令、插件、MCP、浏览器和图片等能力，使用 CLI 内建默认模型及已保存登录授权；不继承日常编程的自定义模型或工具配置。不支持受限调用参数的旧 CLI 显示需更新，不回退到放宽权限的调用。失败、取消、超时或格式不合格的消息保留待重试，不自动提交 coding 任务或发送微信。
